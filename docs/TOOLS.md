# Analysis tools

The game is compiled with **IL2CPP**: there is no C# left in it, only machine code (`GameAssembly.dll`) and metadata (`global-metadata.dat`). Two sources of information:

- the **interop assemblies** generated by BepInEx (`BepInEx\interop\`): class, field, method and enum names… but **not** the method bodies;
- the **machine code** in `GameAssembly.dll`, readable with a disassembler.

The tools in `tools/` are small .NET 8 console programs.

## dumper: list a class

```powershell
cd tools\dumper
dotnet run -- "C:\...\Idle Slayer\BepInEx\interop\Assembly-CSharp.dll" ChestHuntManager ChestType Drop
```

Prints properties (`P`), methods (`M`) and enum values (`E`):

```
## ChestType : System.Enum
  E None = 0
  E Mimic = 1
  ...
## Drop : DataObject
  P System.Double amount {set}
  M Double AddDrop(Double quantity, Boolean surpassLimit)
```

To browse, opening `Assembly-CSharp.dll` in **ILSpy** or **dnSpy** is more comfortable.

## finder: who calls what, and what a method does

Uses LibCpp2IL (shipped with BepInEx) to map machine-code addresses to method names, and Iced to disassemble. The game folder is set with the `IDLE_SLAYER_DIR` environment variable (defaults to the Steam path).

```powershell
cd tools\finder

# Who calls this method?
dotnet run -c Release -- "ChestHuntManager::GenerateChest"
#   Call ... in ChestHuntManager::GenerateChests+0x6B5

# Disassemble a method (strings, types and methods resolved)
$env:DUMP = "SpecialRandomBox::Activate"; dotnet run -c Release
#   005AA  call ...  ; MapController::SpawnPortal
#   006BA  mov rdx,[...] ; "Bonus Stage Portal Appeared"

# Only part of it (hex offsets)
$env:DUMP = "MapController::RandomBoxSpawner"; $env:LO = "1E0"; $env:HI = "260"; dotnet run -c Release

# A specific overload, by address
$env:DUMP = "x"; $env:ADDR = "180356500"; dotnet run -c Release
```

### Example: finding the mimics
1. `dumper ChestHuntManager ChestType Chest` → `chests: List<Chest>`, `Chest.type`, `ChestType.Mimic = 1`.
2. `finder "Chest::SetType"` → only called from `GenerateChest`.
3. `finder "ChestHuntManager::GenerateChests"` → called from `StartEventDelayed`, before the player clicks anything.
4. Conclusion: just read `ChestHuntManager.instance.chests[i].type` during the hunt.

### Example: where a box spawns
The disassembly of `SpawnRandomBox` shows `x = transform.position.x + [rdi+0D8h] + pos.x`: the position argument is an **offset**. The game itself calls `SpawnRandomBox(Vector2.zero)`.

## UI analysis (F11)
In game, `F11` (or Settings → Analyze the UI) writes `BepInEx\slayer_ui_dump.txt`: the tree of every UI object with its size, position, components, sprites and texts. That is how `Shop Panel/Wrapper/Buttons`, the *News* button, the font and so on were found.

```
+ Shop Panel  [1920x1080 @ 0,0]  {Image(Panel), ...}
  + Wrapper
    + Buttons  {HorizontalLayoutGroup}
      + Info  [96x96 @ ...]  {Image(Single Button Square), Button, AnimatedButton}
```

## interopscan: catch interop crashes before testing

Some Unity methods only exist in the interop assemblies as re-implemented code that needs `Il2CppSystem.Span`, and throw `MissingMethodException` at runtime even though the plugin compiles (v6.0.0 crashed on `ColorUtility.TryParseHtmlString`). `interopscan` lists every such method the plugin calls:

```powershell
cd tools\interopscan
dotnet run -- "C:\...\Idle Slayer\BepInEx\interop" "..\..\src\bin\Release\net6.0\SlayerTools.dll"
#   risky interop methods: 1167
#   (nothing listed = OK)
```

## retarget
Rewrites `System.* 8.0.0.0` references in a DLL to `6.0.0.0`. Only useful if you build for `net8.0` (the original sandbox had no NuGet access). With the project as is (`net6.0`), you do not need it.

```powershell
cd tools\retarget
dotnet run -- input.dll output.dll
```
